# 后续开发路线图：刮削、AI 刮削与游戏发送

## 摘要

沿用现有 WPF + SQLite 架构，分五个里程碑推进：

| 里程碑 | 内容 | 依赖 | 风险 |
| --- | --- | --- | --- |
| M1 | 文件名解析刮削 + 预览写库 | 无（纯本地） | 低 |
| M2 | 发送到盘符设备（U 盘 / 掌机存储） | 无 | 低 |
| M3 | AI 刮削（OpenAI 兼容接口） | 用户配置 BaseUrl / Key / 模型 | 中（费用、准确率） |
| M4 | 在线刮削数据源（LaunchBox / TheGamesDB / ScreenScraper） | 用户 Key / 数据包 | 中（配额、匹配率） |
| M5 | 发送到 MTP 设备 | 第三方开源库 MediaDevices | 中高（设备兼容、速度） |

先做 M1、M2，把本地闭环跑通；M3、M4 再接入网络；M5 最后做。每个里程碑独立可验收，不一次性交付。

## M1：文件名解析刮削（本地）

### 目标

不联网，从文件名和平台推断标题、区域、语言、年份，预览后写库；作为后续所有数据源的兜底。

### 新增文件

- `src/MicaRomManager/Models/ScrapeResult.cs`
  ```csharp
  public sealed class ScrapeResult
  {
      public long GameId { get; set; }
      public string Title = "";
      public string Platform = "";
      public string Genre = "";
      public string Region = "";
      public string Language = "";
      public int? ReleaseYear;
      public string Publisher = "";
      public string Developer = "";
      public string CoverUrl = "";
      public string Source = "";
      public bool Changed => ...;   // 与原记录比较，预览时判断是否有差异
  }
  ```
- `src/MicaRomManager/Services/Scraping/FileNameScraper.cs`
  - 规则：
    - 去掉扩展名与括号内容中的区域标记：`(USA)`→美版、`(Europe)`→欧版、`(Japan)`→日版、`(World)`→世界版、`(China)`→国行、`(Korea)`→韩版、`(Taiwan)`→台版、`(Hong Kong)`→港版；
    - 语言标记：`(En,Fr,De)` 等映射到词典（英语、法语、德语…）；
    - 年份：`(1998)` → ReleaseYear；
    - 版本/状态标记（`(Rev 1)`、`(v1.1)`、`(Beta)`、`(Proto)`）从标题移除，可写入 Notes；
    - 碟号标记（`Disc 1`、`CD2`）从标题移除，只提示多碟；
    - 标题清洗：`_`、`.` 转空格，连续空白合并，首尾去空格；保留中文与原有大小写。
  - 平台：沿用记录现有平台；若为空则用扫描时的平台。
- `src/MicaRomManager/Services/Scraping/ScraperService.cs`
  - 输入选中的 `Game` 列表，按启用的数据源顺序执行；
  - 默认「只补空字段」（已有值不覆盖），可切换「覆盖已有值」；
  - 返回预览结果列表。

### 界面

- 主界面工具栏与右键菜单新增「刮削信息…」，多选后可用。
- 新增 `Views/ScrapePreviewWindow.xaml`：
  - 顶部：数据源说明、`只补空字段 / 覆盖已有值` 选项、开始刮削按钮；
  - DataGrid：勾选应用、标题、平台、类型、区域、语言、年份、发行商、开发商、来源；
  - 底部：未选中行提示、取消、应用。
- 应用后逐条 `GameRepo.Update`，刷新列表与筛选。

### 验收

- 文件名 `Super Metroid (Japan) (Rev 1).sfc` → 标题 `Super Metroid`、区域 `日版`、年份空、备注保留 `(Rev 1)`。
- `最终幻想7 (USA) (Disc 1).bin` → 标题 `最终幻想7`、区域 `美版`、提示多碟。
- 已有字段默认不被覆盖；勾选覆盖后才改写。

## M2：发送到盘符设备

### 目标

把选中游戏的 ROM 复制到 U 盘 / 掌机存储（以盘符挂载）的目标目录，可选按平台分文件夹。

### 设计

- 主界面工具栏 / 右键菜单「发送到设备…」。
- `Views/DeviceSendWindow.xaml`：
  - 设备下拉：`DriveInfo` 枚举可移动盘与固定盘（显示盘符、卷标、可用空间）；
  - 目标根目录：默认 `\Roms`，可修改；
  - 选项：按平台子文件夹（默认勾选）、同名文件跳过/覆盖、完成后尝试弹出设备；
  - 选中游戏列表与总大小；开始发送后的进度（当前文件 / 总数）；
  - 结果：成功、跳过、失败、目标路径。
- `src/MicaRomManager/Services/Sending/DriveSendTarget.cs`：
  - 目录创建、逐文件复制、同名策略、异常汇总；
  - 弹出设备可选调用 Windows API（`CM_Request_Device_Eject` 或 shell ` eject`），失败不影响结果。
- 不动源 ROM，只读复制。

### 验收

- 插入 U 盘，选 3 个 PS1 游戏 → 发送到 `<U盘>\Roms\PS1\`，文件名保持原样。
- 同名文件按选择的策略跳过或覆盖；磁盘空间不足时明确报错。
- 发送完成后列表与数据库不变。

## M3：AI 刮削（OpenAI 兼容）

### 目标

用大模型补全中文标题、类型、区域、语言、年份、发行商、开发商和简介，适配 DeepSeek / OpenAI / Ollama / LM Studio 等兼容端点。

### 设置

设置 → 新增「AI 刮削」页（或并入「数据维护」）：

- BaseUrl（如 `https://api.deepseek.com/v1`、`http://127.0.0.1:11434/v1`）；
- API Key（存本地 `settings` 表，界面掩码显示；**不写入仓库任何文档**）；
- 模型名（如 `deepseek-chat`）、超时秒数、每次最多处理条数；
- 测试连接按钮。

### 实现

- `Services/Scraping/AiMetadataProvider.cs`：POST `{BaseUrl}/chat/completions`（`NetworkClientProvider.ApiClient`，带代理）。
  - 请求只发送文本：文件名、平台、现有标题；**不上传 ROM、封面或任何本地文件**。
  - 要求返回严格 JSON：`title_cn / genre / region / language / year / publisher / developer / summary`。
  - 逐条请求，显示进度与已用请求数；失败记录原因并跳过，不自动重试。
- 结果进入同一个刮削预览窗口，确认后才写库。
- 费用控制：默认单次批量上限 50 条，超过时提示分批；不做自动循环。

### 验收

- 配置 DeepSeek 兼容端点后，`Super Metroid (Japan)` 能返回中文标题、类型、年份、发行商。
- 未配置 Key 时按钮禁用并给出提示。
- 网络失败、额度不足、返回非 JSON 时有明确提示，且不改动数据库。

## M4：在线刮削数据源

### 目标

在文件名解析与 AI 之外，接入可插拔的正式元数据源，并支持封面下载。

### 统一接口

```csharp
public interface IMetadataProvider
{
    string Name { get; }
    Task<IReadOnlyList<ScrapeResult>> SearchAsync(IReadOnlyList<Game> games, CancellationToken token);
}
```

### 数据源

- **LaunchBox 本地数据包**（离线优先）：用户指定解压后的数据目录；解析 `Metadata.xml` 与平台 XML，建立「平台 + 归一化标题」索引并缓存；无网络、无配额，适合大批量。
- **TheGamesDB**（免费 Key）：`Games/ByGameName` 查询；限速与缓存；封面 URL 下载到 `CoverStore`。
- **ScreenScraper**（注册账号 + 每日配额）：封面/截图/视频最全；严格限速，逐条显示配额状态；失败不重试。

### 设置

设置 → 「刮削数据源」：启用顺序、Key/账号、LaunchBox 数据目录、缓存清理、测试连接。

### 验收

- 启用 LaunchBox 数据包后，100 条 SNES 游戏可批量匹配，未匹配的保留原值。
- TheGamesDB 能返回封面并写入 `data\covers`；配额超限时提示而不是静默失败。
- 可查看每个条目的命中来源（文件名 / AI / LaunchBox / TheGamesDB / ScreenScraper）。

## M5：发送到 MTP 设备

### 目标

支持以 MTP 连接的 Android 掌机 / 手机类设备，把 ROM 复制到指定存储与目录。

### 设计

- 引入 NuGet `MediaDevices`（MIT，开源）；WPF 中通过该库枚举设备、存储、目录并复制文件。
- `Services/Sending/MtpSendTarget.cs`：实现与 `DriveSendTarget` 相同的发送接口（设备列表、目标路径、进度、结果）。
- `DeviceSendWindow` 设备下拉合并「盘符设备」与「MTP 设备」；MTP 传输逐文件显示当前文件，失败给出明确原因。
- 兼容性：库不可用或设备未授权时，MTP 选项隐藏/置灰，不影响盘符发送。

### 风险与对策

- MTP 传输速度慢、部分设备不支持大文件：分批发送并显示进度；单文件失败不影响其余文件。
- 目录结构差异：发送前让用户选择目标根目录，按平台子文件夹创建。
- 第三方库兼容：先在测试设备验证；若不可用，回退到 Windows WPD/Shell COM 方案作为后备。

### 验收

- 连接 Android 掌机，选择 2 个 ROM → 发送到指定目录，设备端能看到文件。
- 未连接设备、未授权、目标空间不足均有清晰提示。
- 盘符设备发送功能不受影响。

## 通用决策

- **刮削默认只补空字段**，覆盖需显式勾选，避免误改手工整理的数据。
- **所有刮削结果先预览、确认后才写库**。
- 不新增数据库列：刮削结果直接写入现有元数据字段；首发不加「刮削来源/时间」列，减少迁移。
- 网络请求统一走 `NetworkClientProvider`，自动继承现有代理设置。
- 用户填写的 API Key / 账号只存本地 SQLite，不写入仓库文档，也不在日志中输出。
- 封面下载统一走 `CoverStore.Import`，兼容便携模式的相对路径存储。
- 发送功能只读源文件，不改动数据库中的 ROM 路径。

## 建议顺序与理由

1. **M1 文件名刮削**：无网络、无依赖，先把刮削框架和预览 UI 搭好，后续数据源直接接入。
2. **M2 盘符发送**：纯文件复制，风险低，能先解决「把游戏拷到掌机」的核心诉求。
3. **M3 AI 刮削**：需要用户配置端点，作为元数据补全的最强兜底。
4. **M4 在线数据源**：需要 Key 与配额，放在 AI 之后，按需启用。
5. **M5 MTP**：依赖第三方库与真实设备，最后做，避免拖慢前四项。
