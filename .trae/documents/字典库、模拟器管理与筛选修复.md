# 字典库、模拟器管理重做与筛选失效修复

## 摘要

1. **统一字典库**：设置里的「区域 / 语言」改为「字典库」，左侧选择字段类型（区域、语言、平台、类型、发行商、开发商、标签），右侧维护该类型的值；改名级联更新已有游戏记录，被引用的值禁止删除。平台管理的左列表直接来自字典，平台名称只在字典里改。
2. **模拟器管理重做**：左侧模拟器列表，右侧管理面板；功能收敛为导入（文件夹 / 压缩包）、运行调试、打开安装目录、编辑配置、版本更新（打开官网/发布页）、删除。模拟器配置去掉绑定平台、核心文件、配置路径、扩展名，GitHub 仓库改为官网地址；启动参数移到平台设置。
3. **修复筛选失效**：列表内编辑、编辑窗口或批量编辑保存后，筛选条件不再被清空；修改参与筛选的字段后列表按当前条件刷新。

- 模拟器管理是「顶部两排按钮 + 底部 DataGrid」布局（[EmulatorManagerView.xaml](file:///d:/Trae/MICA_ROM_MANAGER/src/MicaRomManager/Views/EmulatorManagerView.xaml)）；配置窗口含绑定平台、启动参数、核心文件、配置路径、扩展名、GitHub 仓库（[EmulatorEditWindow.xaml](file:///d:/Trae/MICA_ROM_MANAGER/src/MicaRomManager/Views/EmulatorEditWindow.xaml)）。

## 一、统一字典库

### 1.1 数据层

`src/MicaRomManager/Data/LookupRepository.cs` 扩展：

```csharp
public const string Region = "region";
public const string Language = "language";
public const string Platform = "platform";
public const string Genre = "genre";
public const string Publisher = "publisher";
public const string Developer = "developer";
public const string Tag = "tag";

public sealed record LookupKind(string Key, string Title);
public static IReadOnlyList<LookupKind> Kinds { get; }
```

新增方法：

- `int CountUsage(string kind, string value)`：统计引用条数。
  - region/language/genre/publisher/developer → 对应 `games` 列；
  - platform → `games.platform` + `platforms` 配置存在也算引用；
  - tag → 读取所有 `games.tags`，按逗号拆分后精确匹配统计。
- `RenameResult Rename(string kind, string oldValue, string newValue)`：
  - 新值已存在 → 失败提示「该值已存在」；
  - 事务内更新 `lookup_items`，并级联：
    - region/language/genre/publisher/developer → `UPDATE games SET <列>=@new WHERE <列>=@old`；
    - platform → `UPDATE platforms SET name=@new`（主键）、`UPDATE emulator_platforms SET platform=@new`、`UPDATE games SET platform=@new`；
    - tag → 逐条读取 `games.tags`，拆分后把完全匹配的标签换成新值，再写回。
  - 返回 `(bool Success, string Message, int Affected)`。
- `DeleteResult Delete(string kind, string value)`：
  - `CountUsage > 0` → 拒绝删除，提示「还有 N 条记录在使用」；
  - 无引用 → 删除 `lookup_items`；platform 额外删除 `platforms` 与 `emulator_platforms` 对应行。

### 1.2 数据库迁移 v9（与下面模拟器改动共用）

- `INSERT OR IGNORE INTO lookup_items(kind, value)`：
  - `platform`：从 `platforms.name` 导入；
  - `genre`：`SELECT DISTINCT genre FROM games WHERE genre<>''`；
  - `publisher` / `developer`：同理；
  - `tag`：C# 读取所有 `games.tags`，拆分去重后写入。
- 保留 region/language 现有数据。

### 1.3 设置页「字典库」

改造 [SettingsWindow.xaml](file:///d:/Trae/MICA_ROM_MANAGER/src/MicaRomManager/Views/SettingsWindow.xaml) 的「区域 / 语言」页：

- 左侧 ListBox：`LookupKind`（区域、语言、平台、类型、发行商、开发商、标签）。
- 右侧：当前类型的值 ListBox + 输入框 + 按钮「添加」「重命名选中」「删除选中」。
- 选中类型时加载对应值；切换类型时清空输入。
- 重命名：输入框填写新名 → 点「重命名选中」→ 调用 `LookupRepository.Rename`，成功/失败弹提示，刷新列表。
- 删除：调用 `Delete`，被引用时提示不可删除及引用数量。
- 平台类型改名后，主界面关闭设置时 `LoadGames()` 会重新加载，筛选值同步更新。

### 1.4 平台管理从字典取名称

- `PlatformRepository.ListAll()`：
  - 读取 `lookup_items(kind='platform')` 的名称列表；
  - 对每个名称调用 `EnsureExists`（写入 `platforms`，保留默认 formats）；
  - 按字典顺序返回 `PlatformSetting`。
- 平台页移除左侧「新增平台 / 删除该平台」按钮（[SettingsWindow.xaml.cs](file:///d:/Trae/MICA_ROM_MANAGER/src/MicaRomManager/Views/SettingsWindow.xaml.cs) 的 `AddPlatform_Click`、`RemovePlatform_Click`），并加提示：`平台名称请在「字典库 → 平台」里维护`。
- 平台字典新增/改名/删除时同步 `platforms` 表（见 1.1）。

## 二、模拟器管理重做

### 2.1 数据与迁移（schema v9）

- `platforms` 新增 `args_template TEXT DEFAULT ''`（平台级启动参数）。
- `emulators` 新增 `website_url TEXT DEFAULT ''`。
- 迁移已有数据：
  - 把默认模拟器的启动参数复制到对应平台：
    `UPDATE platforms SET args_template=(SELECT e.args_template FROM emulators e WHERE e.id=platforms.emulator_id) WHERE args_template='' AND emulator_id IS NOT NULL;`
  - `UPDATE emulators SET website_url='https://github.com/'||github_repo||'/releases' WHERE website_url='' AND github_repo<>'';`
  - `PRAGMA user_version = 9;`
- `emulators` 的 `core_path / config_path / supported_ext / github_repo` 列保留（历史数据），但界面不再显示、不再写入新值。

### 2.2 模型与仓库

- `PlatformSetting` 增加 `ArgsTemplate`；`PlatformRepository` 读写 `args_template`。
- `Emulator` 增加 `WebsiteUrl`；`EmulatorRepository` 读写 `website_url`，保存时不再更新 `emulator_platforms`。
- `EmulatorResolver`：去掉 `repository.GetDefaultForPlatform(...)` 回退；平台未指定默认模拟器时返回 null。
- `RomLauncher`：
  - 启动参数改为 `AppServices.Platforms.Get(game.Platform)?.ArgsTemplate`，为空时用 `"{rom}"`；
  - `{core}` 仍取平台核心（`ResolvePlatformCore`），未配置且模板需要核心时提示去平台设置选核心；
  - `{config}` 不再传入。
- `EmulatorPaths.ResolveConfig` 不再被启动/分享使用。
- `SharePackager`：
  - 不再复制/使用配置路径（`CopyConfig` 调用移除）；
  - 核心改用「平台核心」，缓存键改为 `(EmulatorId, Platform)`；
  - 参数需要核心但平台未配置时保留现有警告并跳过。

## 三、筛选失效修复

`src/MicaRomManager/ViewModels/MainViewModel.cs`：

- `Rebuild` 改为增量同步，不再 `Clear()`：
  - 保留首项「全部平台 / 全部标签」；
  - 删除已不存在的值（跳过首项）；
  - 追加新增值；
  - 若当前选中值不在集合里，再回退到「全部…」。
- `SaveInline` 末尾调用 `ApplyFilter()`，让平台/状态/标签等字段修改后立即按当前筛选刷新。
- 编辑窗口保存（`EditSelected`）、批量编辑（`BatchEdit`）、导入后已有 `RefreshLookups + ApplyFilter`，保持不变。

## 四、决策与假设

- 启动参数统一归平台；模拟器不再有启动参数界面与字段写入。
- 字典改名级联更新所有引用；被引用的值禁止删除（老板已确认）。
- 模拟器版本更新只打开官网/发布页，不再自动检查下载。
- 模拟器绑定平台彻底退役：`emulator_platforms` 表保留但不再维护；启动只认平台设置的默认模拟器。
- 平台名称唯一来源是字典；平台页不再新增/删除平台名称。
- 升级后需要在平台页重新确认一次核心（旧的模拟器核心路径不自动迁移，避免格式不兼容）。
- 不删除旧列、不删代码文件，避免数据丢失与规则冲突；只停止 UI 使用。
