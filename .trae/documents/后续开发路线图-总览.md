## 3. 改动方案

### 3.1 新建 `ROADMAP.md`（仓库根目录）

固定章节：

1. **项目定位与现状**：一句话定位 + v0.13.0 能力概览（6–8 条）。
2. **路线总览表**：「阶段 / 建议版本 / 目标 / 优先级 / 状态」：

   * P0 打磨与收尾（v0.14.x）

   * P1 刮削与发送第一批（v0.15.0–v0.16.0）

   * P2 联网刮削（v0.17.0–v0.18.0）

   * P3 MTP 与增强（v0.19.0+）
3. **P0 打磨现有版本（v0.14.x，高，先做）**

   1. **逐项验收修补**：按 QUEST 从 Q-004 到 Q-014 实操验收，发现的问题就地修，验收完在 QUEST 标「已验收」。
   2. **模拟器更新入口收敛**：解决「官网跳转」与「应用内下载安装」并存但入口缺失的问题；建议保留应用内下载安装（zip/7z + 三种代理），官网跳转降级为兜底；实机跑通下载 → 解压 → 安装 → 版本号回写。
   3. **列表细节**：新增列显隐设置（复用现有列宽/排序/筛选持久化机制）；核对空结果、超长列表、行内编辑后的筛选与状态刷新；工具栏与右键菜单入口保持一致。
   4. **导入与扫描细节**：向导重复项/格式不匹配的提示文案；平台扫描的进度与结果汇总；弃用的 `ImportPreviewWindow` 按规则 11 移到 `toberemoved/`。
   5. **数据维护细节**：指纹补算、失效清理的进度与结果提示核对；大库（约 1000 条）下加载、筛选、扫描的耗时抽查。
   6. **质量基线**：新增/修复项带单测；Release 0 警告、测试全绿、单文件 publish 启动冒烟后方可发版。
4. **P1 近期功能（v0.15.0–v0.16.0，高）**

   * M1 文件名解析刮削：本地规则解析标题/区域/语言/年份，预览确认后写库，默认只补空字段。

   * M2 发送到盘符设备：复制到 U 盘/掌机存储，可选平台子文件夹、同名策略、进度与结果汇总；只读源文件。

   * 详细设计与验收标准沿用现有路线图文档，`ROADMAP.md` 只做摘要并链接。
5. **P2 联网刮削（v0.17.0–v0.18.0，中）**

   * M3 AI 刮削（OpenAI 兼容）：设置页配 BaseUrl/Key/模型/超时/批量上限；结果进同一预览窗口；Key 只存本地。

   * M4 在线数据源：LaunchBox 本地包 → TheGamesDB（免费 Key）→ ScreenScraper 按需。
6. **P3 MTP 与增强（v0.19.0+，中低）**

   * M5 MTP 发送（`MediaDevices`），与盘符发送共用界面，设备不兼容时置灰。

   * 可选：刮削来源/时间列（schema v11，届时评估）、分享包/发送可选带模拟器存档目录。
7. **每版固定流程**：实现 → 构建/测试/发布冒烟 → 更新 CHANGELOG/QUEST → 提交并推送 GitHub（本机需走 `http://127.0.0.1:7890` 代理）。

写作约束：

* 每项写「做什么 / 为什么现在做 / 验收点」，不写时间估算；版本号仅表示建议节奏。

* 状态统一用「已完成 / 进行中 / 待开始 / 待评估」。

* 实现细节不复制，统一以现有路线图文档为准，避免两份文档漂移。
